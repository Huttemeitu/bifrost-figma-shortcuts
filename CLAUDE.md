# Bifrost Figma Plugin

A keyboard-first Figma plugin: running it opens a command palette window where typed commands (`p m g s r l`, `f brand`, `b base-dimmed-3`, `h1`, `button`, `frame alh p m`) or browsable groups apply Bifrost tokens (fill, border, padding, gap, radius, text styles) and auto layout to the selection, or insert frames and Bifrost components.

User-facing usage and the Figma export snippets are in `README.md`. This file is for working on the plugin itself.

## Architecture: a generator plus plain source files

Figma runs `code.js` directly, with no build step on its side. `code.js` and `manifest.json` are **generated**; never edit them by hand.

```
bifrost-variables.json + bifrost-text-styles.json + bifrost-components.json
src/ui.html + src/parse.js + src/runtime.js
        │  node generate.js bifrost-variables.json . bifrost-text-styles.json bifrost-components.json
        ▼
manifest.json + code.js
```

- `generate.js` classifies the exports (COLOR → fill AND stroke, `Spacing/*` → padding + gap, `Border radius/*` → radius, text styles, components) into `VARIABLE_MAP` (slug → `{id, key, name, kind, type, isSet?, group?, px?}`; `px` is a spacing or radius token's default-mode number (`defaultNumber`, following aliases) for value search; `group` is a fill's variable collection or a component's page, the first level of the Options tree), then writes `code.js` = `VARIABLE_MAP` + `UI_HTML` + `src/parse.js` + `src/runtime.js`, concatenated as one classic script (no modules; later files use globals from earlier ones). `UI_HTML` is `src/ui.html` as a JSON string with `src/parse.js` inlined at `/*PARSE_JS*/`, because the palette parses as you type, and the Bifrost tokens as CSS variables at `/*BIFROST_CSS*/` (`bifrostCss`, see Look).
- `src/parse.js` is pure: no `figma` API and no DOM. It runs in three places (plugin sandbox, palette iframe, Node tests via `vm`), so it must stay that way. Top-level `function` declarations are what the test can reach.
- Colors named `Light/...` or `Dark/...` (the Theme collection) are skipped (`MODE_SPECIFIC`): they're the per-mode values behind the Mode collection's tokens, which already follow the parent's variable mode. The user never wants a mode-specific color applied directly.
- Display names are decided in the generator: `textStyleLabel` turns `H1/Satoshi/Text` into `H1`, `componentLabel` prefixes the page name (`Modal/Image`) unless the name already starts with it.

After any change to `src/` or `generate.js`, regenerate and check:

```bash
node generate.js bifrost-variables.json . bifrost-text-styles.json bifrost-components.json
node --check code.js && node --test test/
```

## Runtime model

- The manifest menu is `Open palette` (first, so `bif` → Enter still opens it), `Fix variables` (`fix`, headless `runFix`: binds the review's exact matches) and an `Aliases` submenu with `Alias 0`…`Alias 29` (`figma.command` `alias-N`, `ALIAS_COMMANDS` in `generate.js`). Those run alias `N` headless via `runAlias` → `aliasOps` (in `parse.js`) → `applyOps`, then notify and close. They exist for the companion app (see below), which presses them for numpad digits and recorded shortcuts. Plugin menus are fixed in the manifest (no runtime API), so the commands are numbered slots rather than alias names (decided 2026-10-07; a localhost channel from the companion was the rejected alternative). What a key does lives in the alias; which key runs which slot lives in the companion.
- `Open palette` waits for `clientStorage`, then calls `figma.showUI(UI_HTML, { themeColors: true, ...state.size })` (default 520×600) and the palette takes over. The corner `#grip` in `ui.html` sends `resize {width, height}` once per animation frame while dragging and `save: true` on release; `runtime.js` clamps to `MIN_SIZE`, calls `figma.ui.resize` and stores the size. It replaced Figma's native parameter list (2026-10-02) because that list can't show a right-hand column or open nested groups.
- Message protocol is documented at the top of `runtime.js`. The UI parses locally (instant) and sends `apply {ops, keepOpen}`; the plugin side applies, then either closes (Enter) or replies with `state` (Shift+Enter). Ops carry slugs and labels, so the plugin side never re-parses.
- The palette needs keyboard focus on open (`window.focus()` + `q.focus()`). Not yet verified in Figma whether that works without a click.
- `selectionchange` is forwarded as `selection {count, hasText, hasAutoLayout}`; the UI re-renders live and orders groups by it.
- Palette navigation (in `ui.html`): Enter applies/opens, Tab opens a group or copies the row's `shorthand` into the input for chaining, Esc/Backspace leave a group. Inside a group, input is prefixed with `GROUPS[].prefix` ("m" in Padding parses as "p m"); two words where the first plus the group key is a side op are glued instead (`groupQuery`: "l m" → "pl m").
- Tags: every op from `parse` carries `at` = `[from, to)`, the typed words it came from (alias words all point at the alias, tracked with `src` alongside the expansion splice). `drawTags` in `ui.html` boxes those ranges on `#tags`, a transparent copy of the input text behind `#q` (same font, padding and `word-spacing`, shifted by `q.scrollLeft`), so the input stays a plain `<input>`. The box is a `.tag::before` with negative inset, so it doesn't move the text; it can only grow into the space between words, which is why `word-spacing` is 6px. Ops sharing a span (an alias) get one box; with no `primary`, the last box (from `alternatives[0]`) is dashed. `skip` drops group-prefix words that aren't in the input.
- Right-hand keys per row = `parser.shorthand(ops)` + user aliases whose expansion produces the same label (`aliasIndex`). Single-op rows and Options leaves also show the token's `value` box (`valueHtml`; a swatch when it starts with `#`). Values follow the first selected layer's variable modes: `!vars` exports raw `values` per mode name plus `defaultMode` (aliases kept as `{ alias: id }`, `exportValue`), `generate.js` writes the variables reachable from options into `VARIABLE_VALUES` (single-mode primitives as just the value), `layerModes` in `runtime.js` sends `selection.modes` as `{ collection name: mode name }` (names, since library collections have other ids in consumer files), and `resolveValue`/`formatValue` in `parse.js` resolve and format ("12px", "#1A73E8"). Text styles carry `value: fontSize` instead. Exports without `values` just show no box. Selection changes re-render rows (and the Options tab if open); only the latest async selection message is sent.
- Look (Bifrost, 2026-10-07, replaced a "glass" look): the palette is styled with the library itself. `bifrostCss` in `generate.js` writes every Mode variable as a CSS variable: `bfc-*` colors by token name (`--bfc-base-1`), the rest by path (`--spacing-m`, `--border-radius-s`, `--effect-variables-shadows-blur-m`); Light values in `:root`, Dark ones in `html.figma-dark` (set by `themeColors`), aliases resolved with `valueIn` (other collections at their default mode, so theme colors are Teal). `ui.html` maps a few semantic names onto them (`--text` = base-c-1, `--accent` = theme-1, `--selected` = theme-fade, `--mark` = attn) and otherwise uses tokens directly: a base-2 page with soft theme (teal) and chill (purple) radial glows, base-3 raised surfaces, radius XS/S/M, spacing tokens, theme-filled primary buttons and checkboxes. The focused search field gets a teal-to-purple gradient border (`--gradient` as a border-box background behind a base-3 padding box). Components are copied from the Bifrost Components Figma file (`docKm1Q40SNVPmB7PsezLZ`, one page per component): the help tabs are Tabs "Styled" (a base-1 bar with a bottom border, base-2 content below; 45px tabs with an 8px top radius; the selected one is a base-2 flap bordered on three sides that overlaps the bar's border by 1px via `.tabs { margin-bottom: -1px }`, so no line splits it from the content), and keys, values, counts and examples are Badges (Open Sans semibold, radius XS, Neutral fade colors; Guide examples Theme; the focused row's keys the inverted Theme badge; preview labels inverted Attention). Fonts: `"Satoshi Intility"` for headings, Open Sans for text; the iframe only sees fonts installed on the Mac (not Figma's font service), so Open Sans often falls back to the system font. Never hardcode a color in `ui.html`: add or use a token. The focused palette row is shown by one `#hl` element inside `#list` that glides to the row (`placeHighlight`); it's re-created on every render, so it's placed without animation there and animated in `setActive`.
- The ✓ marks the focused action row (what Enter applies), not the parse result. Re-renders from `state`/`selection` messages call `render(true)`, which keeps focus on the same row (matched by `rowId`) so Shift+Enter doesn't jump back to the top.
- "Run last plugin" (⌘⌥P) isn't usable, so **recents are the repeat mechanism**: `remember()` stores the last 8 commands in `clientStorage`; the palette shows the first 3 runnable ones on top, so Enter right after opening repeats.
- Aliases (`{name: expansion}`, names may be digits like `1`) live in `clientStorage` (per user and machine, not synced; hence Export/Import in the help window). `aliasError` rejects names that are built-in syntax. Aliases are only created and deleted in the help view's Aliases tab; the palette's `=name` syntax was removed (2026-10-06) as confusing.
- Hidden options (`hidden`: array of slugs, set in the Options tab) also live in `clientStorage`. The UI builds its palette parser from entries minus hidden ones, so they vanish from search, groups and counts; aliases, recents and alias validation still use all entries. `setHidden` is fire-and-forget (the UI already updated). Backup JSON is `{ aliases, hidden }`.
- The Options tree comes from `buildOptionTree` (pure, in `parse.js`, tested): kind › group › name path, with one-child levels merged ("Pop/Brand", "Primitives/Teal"). Every node carries `slugs` for whole-group toggles. The filter matches paths below the current node and lists a matching group once instead of its children.
- **Availability is one shared rule** (`parse.js`): `nodeCaps(node)` in `runtime.js` describes a layer (`fills`, `strokes`, `radius`, `corners`, `autoLayout`, `canAutoLayout`, `grid`, `text`), `opNeed`/`opSupports` say what each op needs, and `checkOps(ops, caps[])` walks a command in order: inserts replace the targets with `INSERTED_CAPS`, `alh`/`alv`, padding and gap make frames auto layout, and the first op no target supports returns `{ error, index }`. The palette offers only ops that pass (rows, groups, recents, aliases), with the error as the explanation; `applyOps` runs the same check first and applies each op only to layers where `opSupports` is true. Never add an op without an `opNeed` rule, or it'll be offered where it does nothing. The selection message sends distinct `nodeCaps` (`selection.nodes`).
- Gap (2026-10-07): `g auto` is an op with `value: "auto"` and no slug (`autoGapOp`; `sideValues` adds it to `g`'s values, the Gap group and completions; shorthand `g auto`); `applyGap` sets `primaryAxisAlignItems = "SPACE_BETWEEN"`, and a gap token on such a frame sets it back to `MIN` so the token shows. Its `opNeed` is `"flow"` (a frame, but not grid). `gc`/`gr` (sides `COL`/`ROW`, fields `gridColumnGap`/`gridRowGap`) need `"grid"` (`layoutMode === "GRID"`), so they're only offered on grid frames; plain `g` on a grid binds both grid gaps. The review reads grid gaps instead of `itemSpacing` on grid frames.
- Padding and gap on a frame without auto layout add it (requested 2026-10-06): `opNeed` is `"frame"` (autoLayout or canAutoLayout), `checkOps` returns mode `"autolayout"` so the label reads "Padding M (adds auto layout)", and `applyOp` calls `setAutoLayout(node, guessDirection(node))` first. `guessDirection` mimics Shift+A: children spread wider than tall → horizontal, else (including 0-1 children) vertical.
- Text styles have two modes, decided by `checkOps`: with text in the targets they change it ("Text H5"), otherwise they insert a text layer ("Insert text H5", content "Header H5" for H1-H5, else "Text") via `insertText`, which loads the default and the style's font. `describeOpsIn(ops, modes)` gives the mode-aware labels; `describeOps` (static) is still used for recents and alias matching.
- Inserts (component, frame, text style in insert mode) create a layer: `applyOps` switches its targets to it afterwards, so later ops apply to it (`button p m`, `frame alh h5`). All are placed by `placeNode` (inside a selected auto-layout frame, else after the selection, else viewport center). A component's instance is assumed to be auto layout in `INSERTED_CAPS`, since its contents aren't known before import.
- `WORD_OPS` (`frame`, `alh`, `alv`) are ops with no token: no `slug`, so `applyOps` skips resolving for them, `shorthand` is the word itself, and the palette's Layout group lists them (`list("layout")`, `count.layout` set by hand in `ui.html`). `setAutoLayout` hugs children only when adding auto layout to a frame that has some; empty frames keep their size; instances are skipped.
- **Variable review** (added 2026-10-07): `scanSelection` in `runtime.js` walks the selection and its children (inside an instance only fields in `instance.overrides` count, merged down through nested instances; inherited values belong to the main component) and collects unbound padding, gap (also on frames with no children yet, since it was typed; not with space-between, which is Auto; counter axis only when wrapping), radius, and solid visible fill/stroke paints. Zeros are skipped as noise. Places are grouped by kind + value (+ the layer's modes for colors, `layerModes`) under a string `key`; the last scan lives in `review`, so the palette sends `fixReview {fixes: [{key, slug}]}` and never stale indexes. `reviewChoices` (pure, `parse.js`, tested) gives `{ match, exact }`: one proposal per value, no choice menus, and Fix all takes nearest ones too (asked for 2026-10-07). Sizes: the same `px`, else the nearest (tie → larger: 3 → XS 4). Colors: `reviewColor` tokens only (Mode collection, no theme, effect or primitive tokens), nearest by `colorDistance` in the group's modes; ties by role (`role` "text" → content colors, `isContentColor`, else background colors), then `COLOR_FAMILIES` order (Base, Pop, Miscellaneous), then Pop/Neutral first. `isContentColor` matches `-c` and `-hc` (high-contrast text on a Pop color). Text is restricted to content or Pop colors (asked for 2026-10-08, after a text layer got a Base background color), so white text is `bfc-neutral-hc`. Fill groups carry `role` in their key, since text and shapes get different tokens. `runFix` binds every `match`, like Fix all. Each layer is scanned in its own try/catch; failures come back as `errors` and show as a red row (a single unreadable layer used to empty the whole review). `fixReview` binds fields with `setBoundVariable` and paints by index with `setBoundVariableForPaint`, then `figma.commitUndo()`, and the plugin rescans. The palette's Review view (`reviewView` in `ui.html`) re-requests a scan on every selection change and on `changed`, which the plugin posts 300 ms after `documentchange` settles.
- **Review preview** (2026-10-07): the focused review row is shown in a preview above the list, not on the canvas. A canvas highlight (real layers) was tried first and dropped: ⌘Z brought it back, since Figma splits undo steps itself and plugins can't keep layers out of history, and collaborators saw it. `sendPreview` in `runtime.js` (message `preview {keys, width, height}`) exports the deepest layer containing all of the row's places (`previewRoot`; places in other top-level frames are counted as `elsewhere`) with `exportAsync({ useAbsoluteBounds: true })`, so image pixels map to its `absoluteBoundingBox`. The scale is sharp for twice the palette's zoom (up to 4x, max 4096 px), rounded to steps of √2 so rows reuse images; each `imageId` is sent once per scan (`sentImages`, reset in `startReview`). `previewMarks` gives canvas-coordinate bands (padding per field, `gapStrips`, radius corners), an outline flag (paints, grid/wrap gaps, gaps without strips) and a label (two changes plus "+N more"). In `ui.html`, `syncPreview` requests on focus change or after a rescan (`previewStale`), answers for other rows are dropped, `drawPreview` zooms the focus box to fit and draws marks in preview pixels (labels only with 4 layers or fewer). Blob URLs are replaced per `imageId` (no flicker on rescans) and revoked when leaving the review.
- The loading toast only appears if resolving takes over 400 ms (first import from a library; `slowNotice`). Figma's own "Running Bifrost" indicator can't be controlled.

## Parser rules (src/parse.js)

- `SIDE_OPS` maps op keys (`p`, `px`, `rtl`, ...) to `[kind, side]`; sides map to node fields via `FIELD_SETS` in `runtime.js`.
- **A property is always followed by a space and its value** (`p m`, `rl l`, `rtl s`, `f brand`), decided 2026-10-07. A size can also be its number (`r 12`, `p 12px`; `valueEntry` matches the name first, then `px`), and a partial value completes by name or number (`p 1` → M 12, L 16). The glued form (`pm`, `rl` = Radius L) was removed because L means both left and large: `rtl` read as "Radius top L". Without it there's no shortest-op rule and no alternative readings. Horizontal/vertical are `h`/`v` (`ph l`, `pv s`).
- `splitGlued` recognizes the old glued form (`pm` → `p m`, `fbrand` → `f brand`; a glued color only when the whole word isn't a strong name, `isStrongName`, so `brand`, `button`, `tag` stay searches). `parse` uses it for a "Put a space after the property" error, and `respaceAlias` uses it to rewrite saved aliases: `runtime.js` does that on load (writing back if anything changed) and on import. `matchScore` ignores separators when comparing with the last segment (`base3` = `bfc-base-3`).
- `shorthand` for colors is the key, a space and the compact last segment (`f base3`), only if that parses back to exactly this color. It's computed from a per-kind index (`colorShorthand`), with a real parse only when a path segment collides; a full parse per row took ~850 ms for the Fill group. Results are cached per parser.
- Aliases expand inside the parse loop, only where an op can start (never in a value position), one level deep (`aliasEnd`).
- Word ops are matched before everything else except aliases and fuzzy-op keys; while typing one ("fr", "al"), only its completions are offered.
- `f`/`b`/`t` take one fuzzy word (`bg` for fill was removed 2026-10-06: it made `bgreen` read as fill). Components have no op key (the `+` prefix was removed 2026-10-06 as confusing): they're inserted by name search, and the Component group limits search to components with `GROUPS[].search` → `createParser(..., { search: ["component"] })`. `b` is stroke (label "Border"): `applyOp` binds the color to the first stroke paint and always sets `strokeWeight = 1` (all sides). Stroke isn't in `SEARCH_KINDS`, so a bare color name means fill.
- A name-search run stops before op keywords and aliases (`isKeyword`), so `button b brand` is Button · Border rather than a search for "button b" (every query word only has to start a word in the name, and "b" starts "button").
- Any other word starts a name search over `SEARCH_KINDS` (components, text styles, colors). The **longest run of words that matches a name wins, as long as the words after it still parse**: `basic input p m` = Basic input · Padding M, `icon button` = one name. A name run stops at op keywords and aliases. While typing the last word, alias completions come before name matches.
- Fuzzy ranking (`matchScore`): exact path segment, last-segment prefix, substring or every query word starting a word in the name (any order), then subsequence within one path segment starting at a word start; ties go to non-Font-Awesome names, then kind order, then shorter names. Keep the "word start" rules: looser matching made `box rm` hit "Checkbox-indete**rm**inate". Text-style ranking is known to be weak (`t open` picks Italic before Regular).
- `aliasError` checks names against op syntax only (`createParser(..., { search: false })`), so aliases may shadow name search (`cta`) but not ops (`p`, `rl`, `h1`).
- `SYNTAX` is the help view's Guide tab: sections of `[examples[], meaning]`. Every example is a clickable chip that prefills the palette, so each must parse (enforced by the "every help example parses" test). Keep it in sync with `parse()` and the README table.

## Adding a new kind (e.g. stroke color, effect style)

1. Classify it in `generate.js` (`KINDS`) and map its `type` in `TYPE_BY_KIND` if it isn't a variable.
2. Make sure `RESOLVE_FN` in `runtime.js` can resolve that type.
3. Add a `KIND_LABEL`, an op (in `SIDE_OPS` or `FUZZY_OPS`), a `GROUPS` entry (this also adds it to the Options tree) and a `SYNTAX` row in `parse.js`, and a placeholder in `ui.html`.
4. Handle it in `applyOp` in `runtime.js` (return how many nodes it touched).
5. Add a parser test case, and update the README table and counts.

## Numpad companion app (companion/)

Swift 6 package, macOS 14+, AppKit only. `companion/build.sh` builds a universal `build/Bifrost Numpad.app` (`Info.plist` is copied in, `LSUIElement`), signed ad hoc or with `SIGN_IDENTITY`. `--release` also copies it to `dist/`, which is **committed**: designers install by copying it from a git checkout, with no build tools. That works without notarization only because git doesn't set the quarantine flag (a browser zip download does). Only update `dist/` on a real release (bump the version), since every new binary loses the Accessibility grant.

- `KeyTap.swift`: a `CGEventTap` (needs Accessibility). While Figma is frontmost it swallows recorded shortcuts (also while typing) and numpad digits (keypad key codes, no ⌘⌥⌃⇧, only when `!figma.isTyping`, always `Alias N`), and calls `onCommand` with the Figma menu title; the matching keyUp is swallowed too. While `recorder` is set it swallows every key and captures the next one with ⌘/⌃/⌥ as a `Recording` (⌫ removes, Esc cancels); recording goes through the tap so it also catches combos a window never receives. The menu press is dispatched off the callback so a slow press can't time out the tap. `CGEvent` isn't Sendable, so the callback copies fields into `Key` before `MainActor.assumeIsolated`.
- `Shortcut.swift`: key code + ⌘⌃⌥⇧ flags, saved as JSON in `UserDefaults` (`shortcuts`: Figma command title → shortcut; missing key = only the palette default ⌃⌥Space). The older `paletteShortcut` key is ignored. `description` translates the key code with the current keyboard layout (`UCKeyTranslate`), so Norwegian keys show correctly.
- `Figma.swift`: `isTyping` = the focused AX element is a text role. Works without `AXManualAccessibility` (verified 2026-10-06), so the app never changes Figma's settings. `paletteCommand`, `aliasCommand(n)` and `aliasCount` (must match `ALIAS_COMMANDS`) name the plugin's menu items. `run(command)` finds the item (`Open palette`, `Alias N`) below a menu titled `Bifrost` (dev and org-published paths differ), caches it per Figma pid and searches again if a press fails.
- `main.swift`: status item and menu (Enabled; a "Shortcuts" section with Open palette, Fix variables and an Aliases submenu, each row showing its keys right-aligned and recording on click; launch at login), and the record panel (only an explanation; closing it cancels). Recording a shortcut that another command has moves it. Icon: the Bifrost logo in full color (not a template), highlights the button on success, swaps to `exclamationmark.triangle` on failure, `appearsDisabled` when paused or without permission. Enabled is deliberately not persisted. Launch at login uses `SMAppService.mainApp`. Without permission it polls `AXIsProcessTrusted` every 2 s and starts the tap when granted.
- Icons: `Resources/Logo.png` (1024 px) is the only source. `build.sh` makes the 64 px `MenuIcon.png` with `sips` and the app icon (`AppIcon.icns`, `CFBundleIconFile`) with `app-icon.swift` + `iconutil`. The app icon is full bleed on a dark background because macOS 26+ puts icons that don't fill their square inside a grey rounded square.
- Ad hoc signatures change per build, so macOS forgets the Accessibility grant after every rebuild.
- Before relying on the committed app more widely, check with security: skipping Gatekeeper via git is a gray area. The long-term route is Developer ID + notarization + MDM.

## History

Until 2026-10-02 the plugin had ~1000 menu commands bound to keys through macOS System Settings (plist scripts, curated placeholder lists). That was removed in favor of the prompt, and the user's placeholder rows were deleted from `com.figma.Desktop.plist`. The old setup is in git history if it's ever needed. The throwaway prototype of the prompt lives on the local branch `prototype/prompt`.

## Deploying to Figma

The plugin is registered via **Plugins → Development → Import plugin from manifest…** pointing at this repo's `manifest.json`, so regenerating is enough. Resolvers try the local `id` first, then import by global `key`; the Bifrost libraries must be enabled in the target file.

## Conventions

- Everything is in English: suggestions, `figma.notify` messages, help UI, code comments, docs.
- Comments explain non-obvious *why*, not what the code does.
